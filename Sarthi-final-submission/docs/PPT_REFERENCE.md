# Sarthi - concise PPT reference

Core promise: Find the journey that fits your situation.

1. ENTRY
Situation: first visit -> Welcome -> choose language -> Sign Up / Log In / Guest.
Sign Up: phone -> OTP simulation -> language -> profile -> permission explanation -> Sarthi tour.
Log In: phone -> OTP simulation -> saved profile -> Home.
Guest: planning without permanent history.

2. PLAN
Situation: starting a trip -> New Journey -> Right Now or Pre-Journey -> start + destination -> travel mode -> Journey Priorities -> route comparison.

3. ROUTE INTELLIGENCE
Situation: several practical options -> show 2-4 route cards -> time/cost/walking/transfers/modes -> Why This Route? -> freshness + confidence -> user chooses.
No “safe route” or guaranteed safety claims.

4. LIVE JOURNEY
Situation: journey starts -> live map -> current step -> lightweight step confirmation -> next step -> support.
Live location is active only during the active journey.

5. SOMETHING CHANGED
Situation: transport/weather/connectivity/context changes -> show alert -> explain -> Re-evaluate or Keep current. Never silently reroute.

6. LOW BATTERY / OFFLINE
Situation: battery falls -> 40% Low-Power Journey Mode -> 20% contact update -> 10% stronger battery warning -> 5% essentials only.
Situation: connectivity becomes unstable -> awareness update where possible -> offline-ready.
Journey Capsule created at start stores essential route, steps, checkpoints, help points, destination, support details and timestamps.
Offline screen keeps route/help/checkpoints and compact check-in: I’m OK / Delayed / Need Help / Emergency.
Back online -> Journey synced.

7. JOURNEY STOP
Situation: unexpected stop -> Are you okay? -> light contact buzz after a short window -> stronger escalation if unresolved; context such as traffic can explain delay.

8. EMERGENCY
Situation: user needs urgent help -> Share Location / Get to Safety / Contact Trusted Person / Emergency Information (112).
Emergency view: journey map, last known location, destination, last update, mode and available support context.
Trusted contacts: minimum 5; temporary secure browser link; link expires when journey ends.

9. GET TO SAFETY
Situation: user wants to move to support -> rank nearby legitimate options by distance, availability and available context: police station, hospital, verified help point, public/staffed place, configured trusted person where explicitly available.

10. URGENT EMERGENCY MODE
Situation: manual emergency trigger or unresolved stop -> urgent support flow, trusted-contact alerts, context, help points and navigation guidance. Prototype uses an on-screen trigger; native product can later connect to supported hardware triggers.
Cancellation requires a secret code.

11. REPORTS
Situation: journey/context information changes or evidence is questionable -> Report -> Evidence -> Review -> Verified / Under Review / Questionable / Outdated -> Reopen if still unresolved.

12. FINISH
Situation: destination reached -> Journey Complete -> feedback -> save journey -> live sharing ends -> temporary link expires.
My Journeys: calendar, timeline, map replay, route/mode/events.
Frequent Journeys: suggested recurring patterns.

13. SETTINGS
User-facing controls only: personal information, language, journey preferences/priorities, accessibility, emergency contacts, notifications, privacy, Sarthi tour replay.
No internal challenge/round labels.

14. KEY DESIGN
Hot pink + navy + turquoise + white with orange/yellow for warnings, green for positive states, red only for emergencies. Portrait/mobile-first. Maps support the journey but do not dominate every screen.
